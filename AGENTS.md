# Danesh: instructions for AI coding agents

Shared by Claude Code and Codex. Product, stack and constraints: `.claude/CLAUDE.md` (generated by GSD, do not hand-edit).
Conventions in detail: [docs/conventions.md](docs/conventions.md). Read that before writing code.

## Non-negotiables

- Electron + React + TypeScript only. No Python, no localhost AI servers, no cloud calls. Default-deny network.
- Security boundary: the renderer is sandboxed. It talks to Main/Core only through the closed `window.danesh.call/on`
  API with zod-validated contracts in `packages/contracts`. Never expose Node, `ipcRenderer` or a port.
- Heavy work (PDF, OCR, LLM, TTS) runs in utility processes, never in Main or the renderer.
- Never fabricate content, test results, screenshots or platform verification. Say what was actually run.
- No push, publish, deploy or destructive Git operation without the user's explicit authorization.

## Workflow

- Work through GSD plans in `.planning/phases/*`. Acceptance scenarios (`features/`) are committed before the code
  they cover (`pnpm check:features` enforces it). Keep `STATE.md` and the plan SUMMARY accurate.
- Make the smallest change that solves the problem. No speculative abstractions, packages or folders.
- Before saying a change is done, run: `pnpm check:format && pnpm lint && pnpm typecheck && pnpm depcruise && pnpm test`,
  plus `pnpm test:e2e` for UI, Main, preload or Core changes.
- Commit small, verified increments. Features before their implementation. Never commit model files or secrets.

## Code style (enforced by Biome and ESLint)

- `pnpm format` formats; `pnpm check:format` verifies. Biome covers maintained app, package, tool, step, type and
  root/editor configuration sources. Keep generated output, vendored code and retained license evidence excluded.
- Biome owns formatting, import order and general lint. ESLint owns type-aware and security rules. Do not add rules to
  one that the other already enforces.
- Readable code first: descriptive names, short functions, early returns, no clever one-liners, comments explain why.
- Persian UI text is written in logical order with proper punctuation; never concatenate Latin strings into Persian
  sentences without `<Ltr>`.

## Where things go

See "Layout and dependency direction" in `docs/conventions.md`. If a change needs a new top-level folder or package,
stop and justify it in the commit message or an ADR first.
