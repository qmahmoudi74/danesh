# PDF-02: Extract a PDF's text and read it in Danesh

Owner direction (2026-10-10): after PDF-01, deliver PDF → text extraction → structured blocks → persistent reader
as a working feature. This is an early slice of roadmap Phase 2 (DOC-06…DOC-09, READ-02). It does not complete
Phase 2 or Phase 1. The canonical model is provisional: block kinds are heading and paragraph only.

## What works (Windows, verified)

Library → open a document → «متن استخراج‌شده» → «استخراج متن» → page progress («صفحهٔ ۲ از ۳») → the reader shows
headings and paragraphs as selectable, Persian-first text grouped by page. Each page links back to the original
page, and pages that need OCR or review are listed. After relaunch, the stored text opens without extracting again.
An extraction cut short by closing Danesh shows as interrupted and continues after its last stored page. A stored
original that changed on disk fails its hash check, and nothing is extracted.

- Isolation: a new `pdf` engine host (utilityProcess) runs pdf.js for import checks and page extraction. Core no
  longer parses PDFs. The host reads files through a byte-range transport, so a large PDF is not loaded into
  memory. It keeps one document open and frees each page after use.
- Reading order: pdf.js item order is not used. Items are grouped into lines by baseline, put in visual order by x
  position, then converted to logical order with the Unicode bidi algorithm (`bidi-js`). Mirrored brackets are
  restored, combining marks are attached, and spaces come from gaps. Lines become blocks by leading and font size.
- Raw and normalized text are stored separately. Normalization converts presentation forms, Persian yeh, kaf and
  heh, and digits in Persian text, collapses spaces, and restores ZWNJ only where glyph shapes prove a broken join.
- Stored per page: size, status (`text`, `needs-review`, `needs-ocr`, `empty`) and flags. Stored per block: stable
  id, kind, raw and normalized text, direction, page-relative box, lines with boxes, flags, extractor version
  (`pdfjs-6.4.299+layout-1`). Migration `0004_extraction`; the durable job kernel moves to `0005_jobs.sql`
  (01-13-PLAN.md updated, nothing applied anywhere).

`multi-column-suspected`. These are spot checks, not scored evidence.

## Limits (honest)

- Evidence covers one PDF producer (Chromium/Skia) plus spot checks. Word, LaTeX, InDesign and scanned-then-OCRed
  PDFs are not evaluated, and S-PDF stays open.
- Multi-column pages are flagged, not reconstructed. There are no tables, lists, equations, figures or footnotes
  as block types. Headings are inferred from font size.
- ZWNJ without glyph-shape evidence cannot be restored. Fonts that share glyphs (for example heh doachashmee) can
  name the wrong code point. Only the known heh case is handled.
- No OCR. Scanned pages are only identified.
- Extraction has no cancel button; closing Danesh interrupts it, and «ادامهٔ استخراج» continues it.
- Not run on macOS.
