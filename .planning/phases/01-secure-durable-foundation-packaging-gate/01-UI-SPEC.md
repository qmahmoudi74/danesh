# Phase 1 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> Run mode: `--auto` (no interactive user). Every choice not locked by 01-CONTEXT.md is an **auto-selected default** and is listed in `## Auto-Selected Defaults (audit log)` so a human can audit it.

**Scope (locked by 01-CONTEXT.md D-10, D-11, D-12).** Exactly three user-visible surfaces, plus the blocking start-up states that D-14 and PLAT-04 already require:

1. **Shell (Home):** Persian-first RTL window with the app name and an honest "foundation build" status. No mock reader, curriculum, import button or placeholder that implies functionality.
2. **System check (`بررسی سامانه`):** real diagnostics, per-check pass/fail in plain Persian, expandable technical details, JSON export.
3. **Sample durable job** (inside System check): visible chunk progress that survives kill/restart and visibly resumes.

Everything else (reader, curriculum, import, model manager, settings, themes) is out of scope and appears only under `## Future Extension Points`.

## Spacing Scale

Declared values (all multiples of 4). Only these Tailwind steps may be used for margin, padding and gap:

| Token | Value | Tailwind step | Usage |
|-------|-------|---------------|-------|
| xs | 4px | `1` | Chunk-cell gap, icon-to-text micro gap |
| sm | 8px | `2` | Gap between badge icon and text, gap between check rows, button icon gap |
| md | 16px | `4` | Default padding in rows and banners, gap between related blocks |
| lg | 24px | `6` | Card padding (sample job), gap between sections on System check |
| xl | 32px | `8` | Page inline padding, gap between major blocks on Home |
| 2xl | 48px | `12` | Page block padding (top/bottom) |
| 3xl | 64px | `16` | Not used in Phase 1 (reserved for Phase 3+ page-level spacing) |

Forbidden Tailwind spacing steps: `0.5, 1.5, 2.5, 3, 5, 7, 9, 10, 11 (except min-h-11 below), 14` and every arbitrary value `[..px]` for spacing.

Exceptions:
- Minimum interactive target height/width **44px** (`min-h-11 min-w-11`) for every button and disclosure trigger. 44 is itself a multiple of 4 and is a sizing minimum, not a spacing token.
- 1px hairline borders, 2px focus outline and 2px focus offset are stroke widths, not spacing tokens.
- Chunk cell is a fixed 16px square (`size-4`), radius 4px.
- Layout sizes (not spacing): content column `max-inline-size: 720px`; window default 1040x720, minimum 720x520 (audit log A-11).
- Radius tokens: `--radius-sm: 4px` (chunk cells), `--radius-md: 8px` (banners, rows, buttons, cards). No other radii.

## Typography

Four sizes, two weights (400 and 600). Do not use any other Tailwind size or weight utility (`text-xs/sm/lg/xl/2xl…`, `font-medium`, `font-bold` are banned; use the role utilities below).

| Role | Size | Weight | Line Height | Used for |
|------|------|--------|-------------|----------|
| Body | 16px (1rem) | 400 | 1.75 | Paragraphs, banner body, check result sentence |
| Label | 14px (0.875rem) | 600 | 1.5 | Button text, badges, disclosure triggers, field/section labels |
| Heading | 20px (1.25rem) | 600 | 1.4 | Screen title on System check (`h1`), section titles (`h2`), banner titles |
| Display | 28px (1.75rem) | 600 | 1.3 | App name «دانش» on Home only (`h1`) |

Additional uses of the **same four sizes** (no new size):
- **Caption and technical text:** 14px, weight 400, line-height 1.5. Caption uses `--font-sans` and `--color-text-muted`. Technical blocks use `--font-mono`.
- Root font-size stays 16px; do not set `html { font-size }`. Window zoom (menu) scales everything.

Line-height rationale (auto-selected, audit log A-05): the generic 1.5 body / 1.2 heading recommendation is **not** used because Vazirmatn's tall ascenders and stacked diacritics clip and feel cramped under 1.5/1.2 in Persian. Phase 3's reader defines its own reading scale; these four tokens remain the UI-chrome scale.

Rules:
- Persian prose: never `letter-spacing` (breaks Arabic-script joining). Never `text-transform`. Never italic for Persian.
- Never `text-align: left|right`; use `text-start` / `text-end` only.
- Use ZWNJ (U+200C) inside Persian compounds in copy (see Copywriting), never a regular space or hyphen.
- Numbers shown in primary (non-technical) text go through `formatNumber()` → Persian digits (۰-۹). Technical text keeps ASCII digits.

## Color

Light theme only in Phase 1 (audit log A-03). All colors are semantic CSS variables on `:root` so Phase 3 can add dark and high-contrast themes by overriding the same names. Contrast ratios were computed against WCAG 2.x relative luminance on 2026-10-09.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#FAF8F4` (`--color-surface`) | Window/page background |
| Secondary (30%) | `#F0ECE4` (`--color-surface-raised`) | Sample-job card, banners' neutral base, technical-detail blocks, check-row panels |
| Accent (10%) | `#1B5E8C` (`--color-accent`), hover `#144A70` | See "Accent reserved for" |
| Destructive | not used in Phase 1 | No destructive action exists in this phase. `--color-fail` is a status color only and must not become a button color. A destructive token is added when the first destructive action ships (Phase 12 / UX-10) |

Text and structure tokens:

| Token | Value | Contrast | Usage |
|-------|-------|----------|-------|
| `--color-text` | `#1C1A17` | 16.4:1 on surface, 14.7:1 on raised | Body, headings |
| `--color-text-muted` | `#5C564D` | 6.8:1 on surface, 6.2:1 on raised | Captions, helper text, footer |
| `--color-on-accent` | `#FFFFFF` | 6.9:1 on accent, 9.4:1 on accent-hover | Text on primary button |
| `--color-border-control` | `#8A8378` | 3.5:1 on surface | Borders of interactive controls (secondary button, disclosure trigger) |
| `--color-border-subtle` | `#DDD7CB` | decorative only (1.35:1) | Dividers and card outlines that carry no meaning |
| `--color-focus` | `#0B3D63` | 10.6:1 on surface, 9.6:1 on raised | Focus ring (see Interaction) |

Status colors (always paired with an icon shape and a Persian text label, never color alone):

| Status | Text/icon color | Tint background | Contrast on tint |
|--------|-----------------|-----------------|------------------|
| pass | `#1C6B38` | `#E1F0E4` | 5.5:1 |
| fail | `#A8281F` | `#FAE3E0` | 5.7:1 |
| warn | `#7A4F00` | `#FAEDCC` | 6.1:1 |
| info / running | `#1B5E8C` (= accent) | `#E0ECF5` | 5.8:1 |
| pending | `#5C564D` (= muted) | none | 6.8:1 on surface |

Accent reserved for (explicit list, never "all interactive elements"):
1. The single primary button on each screen (Home «بررسی سامانه»; System check «اجرای بررسی»/«شروع کار نمونه» — at most **one** accent-filled button visible per screen at a time; the other is secondary).
2. Inline text links (the «بازگشت» link, «مشاهده» link on the background-activity line).
3. In-flight indicators: running spinner arc and the sample-job progress-bar fill.
4. The `info` banner icon and tint.

The focus ring uses `--color-focus`, not accent. Secondary buttons are `--color-surface` fill with `--color-border-control` 1px border and `--color-text`.

Forced-colors (Windows High Contrast): all state styling uses `outline`/`border`/`currentColor` (no `box-shadow`-only affordances), and `@media (forced-colors: active)` maps the focus ring to `Highlight` and keeps status icons visible via `currentColor`. Full high-contrast theme is Phase 3 (READ-04); this is the zero-cost baseline.

## Screen Contracts

### Layout (all screens)

- `AppShell`: one centered column, `max-inline-size: 720px`, `margin-inline: auto`, `padding-inline: 32px` (`px-8`), `padding-block: 48px` (`py-12`). Page background `--color-surface`. Footer is pushed to the bottom with `min-block-size: 100dvh` flex column and `margin-block-start: auto`.
- No sidebar, no top bar, no tabs, no in-window nav bar. Navigation = native app menu + in-page link/button (below). Two routes only: Home (`#/`) and System check (`#/system-check`), hash-routed, no router dependency.
- Stack gaps: Home blocks `32px` (`gap-8`); System check sections `24px` (`gap-6`); rows within a list `8px` (`gap-2`).
- Nothing may scroll horizontally at the minimum window width (720px) or at 200% zoom. Vertical page scroll is normal.

### Home

Order (top to bottom): `h1` «دانش» (Display) → status Banner (one of: info foundation banner, or a blocking start-up state) → primary button «بررسی سامانه» → conditional background-activity line (Label with spinner icon, only while the sample job runs/resumes) → footer (version, caption, muted).

- The primary button is the **only** action. There is no import, open, recent-files, search or settings affordance, and no disabled "coming soon" control (brief rule: no mock UI presented as real).
- Starting state: before Core reports ready, the info banner is replaced by the «در حال آماده‌سازی…» line with the running spinner; the button «بررسی سامانه» is rendered but not blocked (System check handles an unreachable Core itself).

### System check

Order (top to bottom): back link «بازگشت» (with `arrow-back` glyph, mirrored for RTL) → `h1` «بررسی سامانه» (Heading) → Intro (Body) → actions row (primary «اجرای بررسی», secondary «ذخیرهٔ گزارش»; wraps below 720px; gap 16px) → export helper/disabled reason (caption) → summary live region (Banner `success`/`error`, or running line) → check list OR empty state → `اطلاعات محیط اجرا` Disclosure → sample-job card (`--color-surface-raised`, padding 24px, radius 8px).

Check list: `DisclosureGroup`, one `CheckRow` per report check, in the report's order (stable; failures are **not** re-sorted to the top). Each row is a 1px `--color-border-subtle` bordered block, radius 8px, padding 16px.
- Collapsed row, inline-start to inline-end: `StatusBadge` (icon + status word), then check name (Label), then the one-line result sentence (Body) below the name, then the `جزئیات فنی` trigger button at inline-end with `chevron-down` (rotates 180deg when open; no horizontal mirroring because it is vertical).
- Expanded panel: `TechnicalDetail` (see RTL & Bidi Contract) with: check id, status, duration in ms, free-text `detail`, plus check-specific fields (engine host entry path inside `app.asar.unpacked`, output hash, probe asset name, fuse bit table, codesign output, connection attempts). Panel background `--color-surface-raised`, padding 16px, radius 8px, max block size 320px and scrollable (focusable region, see Interaction).

## RTL & Bidi Contract

1. **Direction:** `lang="fa" dir="rtl"` on `<html>`; I18nProvider locale `fa-IR`. DOM order equals reading order; never reorder with `flex-row-reverse` or `order-*` to fake RTL.
2. **Logical properties only.** Allowed: `ms-* me-* ps-* pe-* start-* end-* text-start text-end border-s border-e rounded-s rounded-e float-start float-end inset-inline-*`, flex/grid `gap`. **Banned** anywhere in renderer source: `left right ml-* mr-* pl-* pr-* text-left text-right border-l border-r rounded-l rounded-r float-left float-right`, and raw `left:`/`right:`/`margin-left` etc. in CSS. Enforced by a Vitest source-scan test (no new dependency) plus lint. Directional transforms use the `rtl:` variant (`rtl:rotate-180`), never hard-coded `translateX` for direction.
3. **Inline Latin or technical strings inside Persian sentences** (file path, hash, id, version, library name, ISO timestamp, error code) are wrapped in `<Ltr>` = `<bdi dir="ltr">…</bdi>`. Never concatenate them bare. Parentheses and Latin abbreviations inside prose (for example «OCR») also go through `<Ltr>` so the bracket does not flip.
4. **Technical blocks** (`TechnicalDetail`): a `<dl dir="ltr">` (key/value) or `<pre dir="ltr">`, `font-family: var(--font-mono)`, 14px/1.5, `text-align: start` (renders left-aligned because the block itself is LTR), `unicode-bidi: isolate`, `overflow-wrap: anywhere`, `white-space: pre-wrap`. Keys are Latin tokens (`checkId`, `durationMs`, `sha256`); values are never translated. Persian characters inside a path (a Persian Windows profile) must remain readable and in logical order; the verifying screenshot test (UI Considerations) uses a path containing Persian letters, a space and an apostrophe.
5. **Digits:** primary text uses Persian digits via `formatNumber()`; technical blocks and the JSON export use ASCII digits. The Persian-digit **preference** and **Jalali dates** are Phase 3 (UX-02); Phase 1 shows no dates in primary text (timestamps appear only in technical blocks as ISO-8601 UTC).
6. **Punctuation:** Persian forms only in copy: «guillemets» for quotation, `،` `؛` `؟`, and `…` (U+2026) after "در حال …" states. No ASCII `,` `;` `?` or straight quotes in Persian sentences.
7. **Icons:** directional glyphs mirror in RTL (`arrow-back` points toward inline-start, i.e. right in RTL). Non-directional glyphs (check, x, triangle, info, spinner, chevron-down) never mirror.
8. **Progress direction:** `ProgressBar` fill and `ChunkStrip` start at inline-start (right edge) and grow toward inline-end. Use `inline-size`/`width` percentages on a normal-flow block, never `left`/`right` offsets.
9. **Window title:** `<title>` is Persian: Home «دانش»; System check «بررسی سامانه — دانش». Default export file name is ASCII-only (`danesh-system-check-YYYYMMDD-HHmmss.json`) to avoid filename-encoding problems (Pitfalls 33, 35); the save dialog lets the user change it.

## Interaction & Accessibility Contract

**Keyboard**
- Everything is operable by keyboard with a logical Tab order that follows DOM = reading order (right-to-left, top-to-bottom). Home has one tab stop. System check order: back link, Run, Export, each row's trigger, environment trigger, sample-job button(s), sample-job detail trigger.
- Disclosure triggers toggle with Enter and Space. No custom keyboard shortcuts beyond the menu accelerators.
- Every text/scroll region that can overflow (`TechnicalDetail` panels) is a focusable scroll container: `tabindex="0"`, `role="region"`, `aria-label` = «جزئیات فنی {check name}».

**Focus**
- Visible focus on every interactive element: `outline: 2px solid var(--color-focus); outline-offset: 2px;` applied on `:focus-visible` (RAC `data-focus-visible`). Never `outline: none` without this replacement. Under `forced-colors: active` the outline color is `Highlight`.
- On route change focus moves to the new screen's `h1` (`tabindex="-1"`), and `document.title` updates. After Run completes focus stays on the Run button. After the export dialog closes (saved or cancelled) focus returns to the Export button.

**Announcements (no focus stealing)**
- One persistent `role="status"` (`aria-live="polite"`, `aria-atomic="true"`) region on System check carries: run started, run finished with the summary sentence, export result, and sample-job events (started, resumed, completed, failed). Progress ticks are **not** announced; `ProgressBar` exposes `aria-valuetext` («{k} از {N} بخش انجام شد») for on-demand reading only.
- `role="alert"` is used only for run-level errors and blocking start-up errors present at load. Per-check failures are conveyed through the status region summary and the row's own text.

**Status never by color alone:** every status is icon shape + Persian word + color (see Status Vocabulary). Chunk cells add shape + hidden text. Verified by a screenshot test in grayscale in the Tier B evidence set.

**Motion:** the only animation is the 1s linear rotation of the running spinner arc and a `width` transition (150ms ease-out) on the progress fill. Under `prefers-reduced-motion: reduce` both are disabled: the spinner is a static arc glyph (the word «در حال اجرا» remains) and progress snaps. Disclosure open/close has no animation.

**Pointer:** hover state on buttons (accent-hover fill for primary; `--color-surface-raised` fill for secondary), pressed state one step darker, `cursor: default` (native-app feel; `pointer` only on links). Disabled controls use `--color-text-muted` text, no hover, and always have visible adjacent reason text (Export).

**Zoom:** the menu provides zoom in/out/reset. The layout must remain usable (no clipped text, no horizontal scroll) at 200%.

**Security-adjacent UI rules:** the renderer never renders HTML from engine output or the JSON report (text nodes only, no `dangerouslySetInnerHTML`); no `<a href>` to external URLs (all navigation is in-app); no remote fonts, images or icons (CSP `connect-src 'none'`, `img-src 'self' data: blob:`, `font-src 'self'`).
