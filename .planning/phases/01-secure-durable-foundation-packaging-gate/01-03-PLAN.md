## Phase Goal

**As a** learner, **I want to** install Danesh on a clean Windows or macOS machine and have it keep my data durable, private and safe from crashing engines, **so that** I can trust it with my documents and study history.

<objective>
Build the walking skeleton defined in SKELETON.md: the thinnest end-to-end path through every layer the phase touches — Persian RTL window served from `app://` → sandboxed CommonJS preload → private MessagePort → Core utilityProcess → SQLite in the library folder → back to the UI — plus the engine-host hop (Main forks a host on Core's request and brokers the Core↔host port), and the static gates (typecheck, lint, boundary lint, Vitest projects) every later plan uses.

Purpose: prove the architecture on Windows before any durability, packaging or engine work is layered on; every later plan uses the files created here as its in-repo analog (01-PATTERNS.md "after Plan 01, cite the skeleton files").
Output: a runnable test build whose System check shows two passing rows, a playwright-bdd harness, and lint/type/boundary/unit-test configs.
</objective>

Contracts this plan defines (later plans extend, never reshape):
- RPC request envelope: `{ id: positive int, method: string, input: unknown }`; response: `{ id, ok: true, output }` or `{ id, ok: false, error: { code: RpcErrorCode, schema?: string } }`; event: `{ topic: string, payload: unknown }`. `RpcErrorCode` = 'UNKNOWN_METHOD' | 'INVALID_INPUT' | 'PAYLOAD_TOO_LARGE' | 'UNAVAILABLE' | 'READ_ONLY' | 'INTERNAL'.
- `rpcMethods` entries: `{ input: z.ZodType (strict object), output: z.ZodType, maxInputBytes: number }`. Methods in this plan: `system.ping` {n: int 0..1_000_000} → {n, corePid}; `systemCheck.run` {} → {runId}; `systemCheck.get` {runId} → SmokeReport. Events: `systemCheck.progress` {runId, checkId, status: 'running'|'pass'|'fail'|'not-run'}, `systemCheck.finished` {runId}.
- Test-only methods live in `packages/contracts/src/test-rpc.ts` and are merged into the map only when `__TEST_HOOKS__` is true: `test.engineEcho` {} → {hostPid, corePid}.
- Control messages (Main↔Core via process.parentPort / child.postMessage, zod-validated both ways): Main→Core `init` {libraryRoot, appVersion, electronVersion, platform, arch, mainPid, exePath}, `renderer-port` (port attached), `host-port` {kind} (port attached); Core→Main `ready` {corePid}, `spawn-host` {kind: 'sample'}.
- Host protocol (Core↔host port): Core→host `hello`, `run` {taskId, input}; host→Core `hello-ack` {hostPid, kind}, `result` {taskId, ok, output?, errorClass?}, `heartbeat`.
- SmokeReport: {schemaVersion: 1, appVersion, electronVersion, platform, arch, startedAt (ISO-8601 UTC), finishedAt, overall: 'pass'|'fail', checks: CheckResult[]}; CheckResult: {checkId, status: 'pass'|'fail'|'not-run', durationMs: int ≥ 0, detail: string ≤ 2000 chars, fields: record of string|number|boolean, outputSha256?: 64 lowercase hex}. CHECK_ORDER = app-launch, database, cas-storage, engine-llm, engine-ocr, engine-tts, ui-responsive, egress-zero, fuses, codesign.
- Preload API: `window.danesh.call(method, input): Promise<unknown>` (rejects with an Error whose `code` is an RpcErrorCode), `window.danesh.on(topic, cb): () => void`.
- Aliases: `@danesh/<pkg>/<file>.ts` → `packages/<pkg>/src/<file>.ts` (defined once in `aliases.ts`, mirrored in `tsconfig.base.json` `paths`).
