## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Command-line arguments → Main (smoke mode) | `--smoke-test` / `--smoke-out` are attacker-controllable launch arguments in a shipped build |
| Packaged binary on disk → runtime | Fuses and asar integrity decide what code can run |
| Installer → filesystem | NSIS writes the app tree under a user-chosen path |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-19 | Elevation of Privilege | Fuse downgrade or test build shipped | high | mitigate | `electronFuses` production set verified in-app and out-of-process; test build has its own appId/productName/output dir; `assert-no-test-hooks` with positive control; `--publish never` |
| T-01-20 | Tampering | `--smoke-test` mode as attack surface | high | mitigate | `parseSmokeArgs` requires an absolute `.json` path with an existing parent, outside the app/resources dirs, not a symlink; exit 3 before any window/Core on invalid input; no network; only the existing System check + token export path; 300 s overall timeout |
| T-01-21 | Denial of Service | NSIS silently dropping files past MAX_PATH | high | mitigate | Narrow `asarUnpack`; build manifest + installed-tree diff; UTF-16 path bound < 260 for a 40-character Persian user name |
| T-01-22 | Spoofing | Unsigned (Windows) / ad-hoc signed (macOS) binaries | medium | accept | D-08: no paid signing in Phase 1; real signing is REL-03 in Phase 12; codesign strict verification still proves bundle integrity on macOS |
| T-01-SC | Tampering | npm/pip/cargo installs | high | mitigate | No new packages; electron-builder downloads its NSIS/Electron zips from its own pinned sources at build time (dev machine only) |
</threat_model>
