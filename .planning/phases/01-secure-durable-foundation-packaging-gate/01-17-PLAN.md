# Plan 01-17: Custom desktop shell, themes and design system

<objective>
Implement the user's 2026-10-10 product-design requirements on top of the completed Plan 01-06 UI: a fully custom
window shell (frameless window, own title bar and controls, native behavior preserved), System/Light/Dark themes with
no start-up flash, a maintainable token-based design system, deliberate scrolling, a consistent motion language and
pixel-level polish — without weakening Main/Preload/Renderer security boundaries.

Why now and why a separate plan: 01-06 is complete and verified, so its record stays untouched. 01-17 depends only on
01-06 and runs before 01-07 so that 01-07's IPC/window hardening covers the new shell methods as well.
</objective>

<context>
- Design contract: 01-UI-SPEC.md, section "Amendment A — Desktop shell, themes and design system (2026-10-10)".
  Amendment A supersedes the UI-SPEC lines that said "no top bar / no sidebar", "light theme only" (A-03),
  "color-scheme: light" and "the only animation is the spinner". Everything else in the UI-SPEC remains in force.
- Security: new shell methods go through the existing danesh:shell handler (sender + top frame + trusted origin,
  strict schema, byte limit) — no new preload keys, no raw ipcRenderer, no Node in the renderer.
- Persistence choice: UI preferences (theme, window bounds) are shell state, not learning data. Main must know them
  synchronously before creating the window, and Main never opens the database (01-03 boundary), so they live in a
  small schema-validated, atomically written JSON file next to the database. Sidebar collapse is a per-view
  convenience kept in renderer localStorage (wrapped in try/catch).
</context>
